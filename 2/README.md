# Паттерны проектирования — шпаргалка

Статья: https://selectel.ru/blog/pesign-patterns/

## Что такое паттерн

Паттерн — это **готовое решение частой задачи** при проектировании кода.
Это не библиотека и не команда, а **приём**, как лучше устроить классы. Как рецепт.

**Зачем нужны:** код понятнее, его легче менять, у программистов общий язык («тут Одиночка»).

## Классификация — 3 группы

| Группа | Вопрос | Файл | Сколько |
|---|---|---|---|
| **Порождающие** | Как **создать** объект? | `1_creational.py` | 5 |
| **Структурные** | Как **соединить** объекты? | `2_structural.py` | 7 |
| **Поведенческие** | Как объектам **общаться**? | `3_behavioral.py` | 11 |

Запуск: `python3 1_creational.py`

## Основы Python (если спросят по коду)

- `class` — чертёж, объект — вещь по чертежу (`Coffee()`)
- `def` в классе — **метод**, то, что объект умеет
- `self` — «этот самый объект»
- `__init__` — запускается при создании объекта
- `return self` — позволяет писать вызовы цепочкой

## 1. Порождающие

| Паттерн | Суть одной фразой | Пример в коде |
|---|---|---|
| **Одиночка** (Singleton) | У класса только **один** объект | `Config()` — `a is b` → `True` |
| **Фабричный метод** (Factory Method) | Класс сам решает, **какой** объект создать | `RoadDelivery` → грузовик, `SeaDelivery` → корабль |
| **Абстрактная фабрика** (Abstract Factory) | Создаёт **набор** подходящих объектов | `DarkTheme` → тёмная кнопка + тёмный текст |
| **Строитель** (Builder) | Собираем объект **по шагам** | `PizzaBuilder().set_size(30).add("сыр").build()` |
| **Прототип** (Prototype) | Новый объект = **копия** старого | `doc.clone()` через `deepcopy`, оригинал не меняется |

## 2. Структурные

| Паттерн | Суть одной фразой | Пример в коде |
|---|---|---|
| **Адаптер** (Adapter) | **Переходник** между несовместимыми интерфейсами | тенге × 100 → тиыны для старой системы |
| **Мост** (Bridge) | Две части отдельно, любую с любой | `Remote(TV())`, `Remote(Radio())` |
| **Компоновщик** (Composite) | Одна вещь и группа вещей работают **одинаково** | `Box` внутри `Box`, у всех `price()` |
| **Декоратор** (Decorator) | **Оборачиваем** объект и добавляем новое | `Milk(Milk(Coffee()))` → 800 + 200 + 200 |
| **Фасад** (Facade) | **Одна кнопка** вместо сложной системы | `order()` = склад + оплата + курьер |
| **Приспособленец** (Flyweight) | Общие данные храним **один раз** — экономия памяти | 1000 деревьев, 1 тип |
| **Заместитель** (Proxy) | **Охранник** перед объектом | не admin → «Нет доступа» к базе |

## 3. Поведенческие

| Паттерн | Суть одной фразой | Пример в коде |
|---|---|---|
| **Цепочка обязанностей** (Chain of Responsibility) | Запрос идёт **по цепочке**, пока кто-то не обработает | менеджер → директор → отказ |
| **Команда** (Command) | Действие = объект, можно **отменить** | `do()` / `undo()` как Ctrl+Z |
| **Интерпретатор** (Interpreter) | Каждое правило языка = класс | `Plus(Num(2), Num(3)).calc()` |
| **Итератор** (Iterator) | Перебор **по одному** | `for song in Playlist(...)`, метод `__next__` |
| **Посредник** (Mediator) | Общение **через центр**, а не напрямую | пользователи пишут через `Chat` |
| **Хранитель** (Memento) | **Сохранить** и вернуть состояние | `save()` / `load()` в игре |
| **Наблюдатель** (Observer) | **Подписка**, всех уведомляют | новое видео → все подписчики узнают |
| **Состояние** (State) | Поведение зависит от **статуса** | новый → оплачен → доставлен |
| **Стратегия** (Strategy) | **Подменяемый** алгоритм | `NoDiscount` / `StudentDiscount` |
| **Шаблонный метод** (Template Method) | Родитель задаёт шаги, дети меняют **один шаг** | `Exporter` → CSV или текст |
| **Посетитель** (Visitor) | Новое действие **без изменения** классов | `AreaVisitor` считает площадь фигур |

## Возможные вопросы на защите

**Чем Фабричный метод отличается от Абстрактной фабрики?**
Фабричный метод создаёт **один** объект. Абстрактная фабрика создаёт **семейство** связанных объектов.

**Чем Декоратор отличается от Заместителя?**
Декоратор **добавляет** новое поведение. Заместитель **контролирует доступ** к объекту.

**Чем Стратегия отличается от Состояния?**
Стратегию выбирают **снаружи** (какую скидку применить). Состояние меняется **само** внутри объекта (заказ перешёл в «оплачен»).

**Чем Фасад отличается от Адаптера?**
Фасад **упрощает** сложную систему. Адаптер **подгоняет** один интерфейс под другой.

**Зачем Одиночка?**
Когда объект должен быть один на всю программу: настройки, подключение к базе, логгер.

**Минусы паттернов?**
Если применять их без необходимости, код становится сложнее, чем нужно.
